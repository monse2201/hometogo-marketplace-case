Hands-On Product Analytics

SQL Analytics

The product owner does not need to build the matching model, but should be able to independently investigate data quality, evaluate model performance and challenge assumptions with data.

duplicate_rate_by_partner.sql BigQuery 
SELECT
  partner_name,
  COUNT(*) AS total_listings,
  COUNTIF(
    canonical_property_id IS NOT NULL
  ) AS matched_listings,

  ROUND(
    COUNTIF(duplicate_flag = TRUE)
    / COUNT(*) * 100,
    2
  ) AS duplicate_rate

FROM
  marketplace.listings

WHERE
  listing_status = 'ACTIVE'

GROUP BY
  partner_name

ORDER BY
  duplicate_rate DESC;
quality_vs_conversion.sql BigQuery 
WITH listing_performance AS (

  SELECT
    listing_id,
    quality_score,
    COUNT(DISTINCT session_id)
      AS listing_views,

    COUNTIF(booking_id IS NOT NULL)
      AS bookings

  FROM
    analytics.listing_sessions

  GROUP BY
    listing_id,
    quality_score
)

SELECT
  CASE
    WHEN quality_score >= 90 THEN '90-100'
    WHEN quality_score >= 80 THEN '80-89'
    WHEN quality_score >= 70 THEN '70-79'
    ELSE 'Below 70'
  END AS quality_band,

  SUM(bookings)
  / SUM(listing_views)
  AS conversion_rate

FROM
  listing_performance

GROUP BY
  quality_band;

STRATEGY C-LEVEL
Product Judgment

Decisions & Trade-offs

Marketplace infrastructure rarely has a universally correct answer. Product ownership means making explicit trade-offs, defining guardrails and connecting technical decisions to traveler and commercial outcomes.

01 · Should matching optimize for precision or recall?

A false merge can combine two genuinely different accommodations, potentially showing incorrect prices, availability or content. A missed match creates duplicate inventory and reduces search diversity. The cost of the two errors is not symmetric.

Decision Bias toward precision for automatic merges.
Guardrail Ambiguous candidates enter a secondary review or confidence layer.
Measure False merge rate + duplicate exposure + booking CVR.

02 · Should every missing attribute reduce Quality Score equally?

No. Missing Wi-Fi information and missing decorative description text have very different traveler impact. The score should reflect expected downstream value rather than treating completeness as a simple field count.

Decision Weight attributes according to traveler relevance and observed conversion impact.
Guardrail Prevent high commercial performance from hiding inaccurate critical fields.
Measure Quality dimension vs. CTR, conversion and customer issues.

03 · Build AI-specific inventory or improve the core data model?

Creating a parallel AI catalog would accelerate short-term experimentation but introduce another source of truth. A stronger canonical accommodation model creates leverage across search, APIs, LLM discovery and future distribution channels.

Decision Improve the canonical model first; expose AI-specific representations downstream.
Guardrail Do not delay experiments that can validate AI discovery demand cheaply.
Measure Structured coverage + retrieval accuracy + distribution reach.
Product Thesis

Marketplace data infrastructure is not a backend cost center. It is a growth product.

Better entity resolution improves discovery. Better catalog quality increases traveler confidence. Better structured data expands distribution. The product owner's job is to connect those infrastructure improvements to measurable marketplace outcomes.
